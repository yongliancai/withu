# 個資外洩 72 小時應變流程（伴旅 WithU）

依企劃書「安全、隱私與法規」：新版個資法草案要求知悉外洩後 72 小時內通知當事人；涉及特種個資、影響 100 筆以上或保有 1 萬筆以上，需通報主管機關。測試版雖然規模小，仍照這個流程做。

## 0 小時：發現
可能的來源：後台「系統紀錄」出現大量錯誤、主機異常登入、測試者回報看到別人的資料、雲端或 OpenAI 通知。

1. 記下發現的時間（72 小時從這裡算）。
2. 先止血，不要刪任何紀錄：
   - 疑似帳號或金鑰外洩：立刻更換 `ADMIN_TOKEN`、`OPENAI_API_KEY`、VAPID 金鑰、GitHub Deploy key，`pm2 restart companion`。
   - 疑似主機被入侵：在 CloudPanel 改 root／liancai 密碼，必要時先 `pm2 stop companion` 暫停服務。
3. 備份目前狀態做為證據：`cp -r data ~/incident-$(date +%m%d%H%M)`，另存 `pm2 logs` 與 nginx 存取紀錄。

## 24 小時內：釐清範圍
- 哪些資料：對話、記憶、照片、語音、動態、暱稱、登入碼？有沒有健康、性等敏感內容？
- 影響幾位使用者（後台「測試者」可查）。
- 怎麼發生的、是否已經堵住。
- 把以上寫成一頁紀錄（時間軸、範圍、處置）。

## 72 小時內：通知
**通知受影響的使用者**（App 內公告＋測試群組訊息），內容包含：
1. 發生了什麼事、什麼時候
2. 影響哪些資料
3. 我們已經做了什麼
4. 你可以做什麼（例如到「設定 → 隱私與資料」下載或刪除資料、更換登入碼）
5. 聯絡方式

**通報主管機關**：涉及特種個資、影響 100 筆以上，或整體保有 1 萬筆以上時，依當時有效的法規與主管機關公告辦理（新版個資法施行細則公布後再確認窗口與格式）。

**供應商**：若起因在 Hostinger 或 OpenAI，同步向對方回報並要求事件說明。

## 事後
- 一週內寫檢討：根本原因、改善措施、要追蹤的事項。
- 更新本文件與 `public/privacy.html`。

## 平常就要做的
- `data/` 每週備份到另一個地方。
- `.env` 不進 GitHub（已在 `.gitignore`）。
- 後台 `ADMIN_TOKEN` 用長亂碼，不和其他服務共用。
